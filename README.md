# Dissipative Neural Network Controller

This repository contains code for training neural-network controllers for custom Gymnasium/MuJoCo inverted pendulum environments and refining the trained policies using dissipativity-based optimization.

## Overview

The workflow has two stages:

1. **RL training (`ddpg_train.py`)**
   - Trains a DDPG actor-critic controller.
   - Supports linear, normal, and residual actor architectures.
   - Saves actor checkpoints, TensorBoard logs, and evaluation videos.

2. **Dissipativity-based policy refinement (`policy_refinement.py`)**
   - Loads trained actor checkpoints from the `saves/` directory.
   - Solves constraint optimization problems using CVXPY and MOSEK.
   - Refines the controller parameters subject to dissipativity/stability constraints.
   - Produces a neural-network controller with a dissipativity-based stability guarantee when the optimization problem is feasible.
   - Generates response plots, norm plots, data files, and optionally videos.

## Two Python environments

Use separate environments for the two stages.

### RL training environment

Use `requirements_train.txt` when running `ddpg_train.py`. This environment contains PyTorch, PTAN, Gymnasium, MuJoCo, and the video-recording dependencies. It does not need CVXPY or MOSEK.

```bash
conda activate rl_env
python -m pip install -r requirements_train.txt
```

### Policy-refinement environment

Use `requirements_refinement.txt` when running `policy_refinement.py`. This environment contains CVXPY and MOSEK, which are required for the constraint optimization step.

```bash
conda activate refinement_env
python -m pip install -r requirements_refinement.txt
```

The two environments should be kept separate because the refinement environment and the training/video environment may have incompatible package combinations, especially around CVXPY/MOSEK, NumPy, Gymnasium, and video recording.

## RL training

Run training from the repository root so that the relative paths to `lib/`, `custom_xml/`, and `saves/` are resolved correctly.

The `--name` argument is required. A basic example is:

```bash
conda activate rl_env
python ddpg_train.py \
    --dev cuda \
    --name custom \
    --model residual \
    --actor_layer 20 10 \
    --critic_layer 100 75 \
    --environment NetworkInvertedPendulum-v0 \
    --directory lib.custom_model:NetworkInvertedPendulumEnv \
    --best_reward 850 \
    --seed 0
```

The script creates a directory similar to:

```text
saves/ddpg_custom_0_residual_a_20_10_c_100_75_MMDD_HHMM/
```

The directory contains actor checkpoints and videos generated when a new best evaluation reward is obtained.

### `ddpg_train.py` arguments

| Argument | Meaning | Default |
|---|---|---|
| `--dev` | PyTorch device, for example `cpu` or `cuda` | `cpu` |
| `-n`, `--name` | Name used in the output directory and TensorBoard log | required |
| `-m`, `--model` | Actor type: `normal`, `linear`, or `residual` | `normal` |
| `-al`, `--actor_layer` | Hidden-layer dimensions of the actor | `20 10` |
| `-cl`, `--critic_layer` | Hidden-layer dimensions of the critic | `100 75` |
| `-env`, `--environment` | Registered Gymnasium environment ID | `NetworkInvertedPendulum-v0` |
| `-dir`, `--directory` | Gymnasium entry point in `module:Class` form | `lib.custom_model:NetworkInvertedPendulumEnv` |
| `-best`, `--best_reward` | Target reward used by the training logic | `850` |
| `--seed` | Random seed | `0` |

For example, to train a linear actor with a different seed:

```bash
python ddpg_train.py --dev cuda --name custom --model linear \
    --actor_layer 20 10 --critic_layer 100 75 \
    --environment NetworkInvertedPendulum-v0 \
    --directory lib.custom_model:NetworkInvertedPendulumEnv \
    --best_reward 850 --seed 1
```

Use `python ddpg_train.py --help` to print the available arguments.

## Dissipativity-based policy refinement

Before running refinement, make sure that the checkpoint paths in `policy_refinement.py` point to existing files under `saves/`. The script currently stores these settings in `SimpleNamespace` lists near the bottom of the file rather than exposing them through command-line `argparse` options.

For each checkpoint, update:

```python
SimpleNamespace(
    model="best_+975.574_1200000.dat",
    actor="linear",
    directory="saves/linear/ddpg_custom_0_linear_a_20_10_c_100_75_0703_2211",
    environment="CustomCartPole-v0",
    env_directory="lib.custom_model:CustomCartPoleEnv"
)
```

Change the following values as needed:

- `model`: checkpoint filename.
- `directory`: directory containing that checkpoint.
- `actor`: actor structure, either `linear` or `residual` in the current script.
- `environment`: Gymnasium environment ID.
- `env_directory`: Gymnasium entry point in `module:Class` form.

Global refinement settings are defined near the top of the file:

```python
L2_DIST = "sinc"       # sinc, exp, or inv_prop
DT = 0.001
CUTOFF = 4
VIDEO_SAVE = False
```

The controller construction settings are defined where `ControllerSynthesis` is created:

```python
device="cuda"
linear_gear=300
rotational_gear=30
struct="linear"       # or "resnet"
verbose=True
```

The current `policy_refinement.py` does not parse command-line arguments even though it imports `argparse`. Therefore, edit these values in the file before running it, or add an `argparse` interface if command-line configuration is preferred.

Run refinement from the repository root:

```bash
conda activate refinement_env
export MOSEKLM_LICENSE_FILE=/path/to/mosek.lic
python policy_refinement.py
```

The script compares the trained controllers with the refined controllers and writes plots and trajectory/action data under `results/`. If `VIDEO_SAVE = True`, it also writes MuJoCo videos under `video/`.

## MOSEK license

`policy_refinement.py` requires a valid MOSEK license. The script currently sets `MOSEKLM_LICENSE_FILE` near the top of the file. Update that path for the machine on which the code is run, or export the variable before execution:

```bash
export MOSEKLM_LICENSE_FILE=/path/to/mosek.lic
```

## TensorBoard

Training logs can be viewed with:

```bash
tensorboard --logdir runs
```

Then open the URL printed by TensorBoard.

## Notes

- Run scripts from the repository root.
- Keep the `custom_xml/` files together with `lib/custom_model.py`.
- Checkpoint filenames and directories in `policy_refinement.py` must match files produced by `ddpg_train.py`.
- A refinement result is stability-guaranteed only when the corresponding optimization problem is feasible and the stated certificate assumptions apply.
